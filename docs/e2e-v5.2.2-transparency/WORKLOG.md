# E2E v5.2.2 — ПРОЗРАЧНОСТЬ СТРИМА: мешает ли транспорт игре?

## Вопрос пользователя

«Стрим не мешает игре? Он как бы прозрачный?»

## Метод

Свежий стенд после очередного сброса песочницы: restore_env.sh (rust 1.99.1,
JDK 25.0.5, glslang 16.6.0) + setup_client.py (5147/5147 ассетов) + boot_server.sh
(все гейты OK) + run_client.sh, пак принят одним кликом. Стрим v5.2.2 на полной
мощности: particles_per_tick=2048, окно 512x512 (origin 0,64).

## Результаты

### 1. TPS сервера под полной нагрузкой стрима

| момент | TPS 1m / 5m / 15m |
|--------|--------------------|
| ранняя фаза (шторм генерации чанков + скан) | 19.1 / 19.4 / 19.4 |
| устойчивый режим (двелл в вантаже, 13.3M частиц отстреляно) | **20.0 / 20.0 / 19.9** |

Вывод: просадка ранней фазы — генерация чанков сканом (известная цена
FORCED-тикетов), НЕ транспорт. В устойчивом режиме стрим не двигает TPS.

### 2. Надёжность транспорта

`stream: tick 6800 16336/65536 cells, lap 332, +2048 particles (1 players),
spawned 13325312 / failed 0` — 13.3 миллиона частиц, ноль отказов.

### 3. Видимость частиц (кадры)

- `shots/s_ground.png` — выживание с земли у спавна (внутри активной зоны
  стрима, 1152+ клеток отсканировано): кадр ЧИСТЫЙ, ни одной видимой частицы,
  HUD обычный. Обычная игра стрим не показывает.
- `shots/s_final_level.png` — худший случай: spectator Y=280, взгляд в диск
  с вантажа. Видна редкая россыпь крошечных (1-2 px) тёмных точек — колонны
  частиц над просканированными клетками. Это максимум того, что видно глазу,
  и только с высокой точки.
- `shots/s_dwelling.png`, `shots/s_vantage4.png` — промежуточные кадры двелла
  (туман/небо — llvmpipe догоняет рендер с лагом, см. заметки по стенду).

### 4. Архитектурная прозрачность (без новых замеров, из кода)

- Транспорт = ClientboundLevelParticlesPacket (happy_villager, count=0,
  force) — ноль сущностей/блоков/коллизий, не влияет на ИИ, спавн, свет.
- capture-пасс read-only: читает готовый кадр, экран не меняет.
- lod_terrain рисует ТОЛЬКО небесные пиксели (depth-правило) — реальная
  геометрия всегда выигрывает; ближе ~256м краски нет вообще (fog).
- force-режим: частицы переживают «Частицы: минимум» — осознанный трейдофф
  транспорта (capture должен видеть их с любой дистанции).
- Сеть: 2048 пак/тик = ~41k пак/с на игрока в зоне диска (~10-30 Мбит/с) —
  цена канала; бэклог: дельта-режим (после первой лапы слать только
  изменившиеся клетки).

## Заметки по стенду (26.3 / llvmpipe)

- 6-арг форма `tp <target> <x> <y> <z> <yaw> <pitch>` в 26.3 = «Incorrect
  argument». Работает `facing`.
- Относительные координаты из КОНСОЛИ резолвятся от контекста консоли
  (спавн), а не от игрока: `execute as X run tp @s ~5 ~ ~` уводит не туда.
  Правильно: `execute at @p run tp @p ...`.
- Клиент llvmpipe рендерит с лагом в секунды: кадр через 3-15 с после tp
  может быть устаревшим; рабочие двеллы — 90-240 с (подтверждает протокол
  v5.2.2).
- boot_server.sh ждёт /home/z/tools/jdk25 — restore_env.sh теперь создаёт
  этот симлинк (было только ~/mc-test/jdk25).
