Полный сброс песочницы → восстановление по `scripts/bench/restore_env.sh`
(cargo 1.99.1, Temurin 25.0.5, glslang 16.6.0, клиентский рантайм 66/66 lib +
5147/5147 assets, shim, dist). liblod.so v5.2.0: 35/35 тестов, clippy 0,
GLSL 11/11. ALL GATES PASSED на Paper 26.3, пак пушится ровно один раз
(49879 bytes, sha1 baf07239).

## Что нового в v5.2.0: сглаживание хайтфилда

`assets/glsl/lod_terrain.fsh`: дистанционный вес `smooth_w(96..288)` +
усреднение 2x2 клетки декодированных значений (высоты и RGB 6x6x6-решётки),
только валидные соседи — фронт данных остаётся точным, вода через флаг
большинства. Убивает крап альбедо 2-блочных клеток на 400 м (находка
v5.1.1). NEAREST сохранён внутри 96 блоков (баг v4.2 с билинейкой не
возвращается).

## Восстановление стенда: что оказалось тяжёлым

1. `fill`/`setblock` с `~` через `execute as ... at @s` из КОНСОЛИ 26.3
   молча не работает (tilde не резолвится) — `say`/`list` работают, plain
   `fill` с абсолютными координатами работает ("Successfully filled 49
   block(s)"). Башню строили циклом: `fill -932 Y 793 -926 Y 799 glass` +
   `tp Stepan -929.5 Y+1 796.5 0 90`, Y += 4, до 113 (11 итераций).
2. Игрок в выживании падал с каждой площадки и умирал дважды. Креатив
   (`gamemode creative`) делает падения безопасными; double-tap пробела
   (полёт) на llvmpipe 1-2 FPS не срабатывает — игнорируем, башня надёжнее.
3. Ответы консоли приходят с лагом 5-10 с (сервер async) — между командами
   sleep 2.5 с, после data get — 6-8 с.
4. `data get entity Stepan Pos` — главный способ подтвердить высоту
   (Y=114.0 на стеклянной площадке 117... точнее 113 + tp 118).

## Методика A/B (кадры в shots/)

Стеклянная башня (-929.5, Y=113..118, 796.5) над центром диска (-930,796),
камера pitch 20 вниз: лучи над кронами уходят за край рендера чанков
(~256 м) и бьют в стриминговый хайтфилд. ON-кадр → `posteffect remove
Stepan clod:lod_terrain` → OFF-кадр → re-add. Diff numpy >15.

| кадр | что показывает |
|------|----------------|
| 01_tower_y114_day | башня 7x7 стеклянных площадок, день (time set 6000 x3) |
| 02_horizon_ON + 03_AB_horizon | горизонт-лента краски с Y=114, diff 7430 px |
| 05_high65_ON | pitch 65 вниз: лучи бьют в ближние клетки — их закрывают чанки, diff 136 px (ожидаемо) |
| 06_p20_ON / 07_p20_OFF | главный ракурс: pitch 20 вниз с Y=118 |
| 08_AB_p20 | A/B: diff **112031 px** (49% окна) |
| 09_diffmask | маска diff: сплошной клин краски от прицела вправо-вниз |
| 10_amplified_diff | diff x8: (1) верх — точки движущейся пыли (стрим живой), (2) середина — ГЛАДКИЕ дуговые полосы краски без крапа = работа smooth_w, (3) низ — анимация воды/листвы (ваниль) |
| 11/12_zoom_ON/OFF | зум горизонт-ленты: ON плотнее и структурнее |

## Выводы

1. **Краска доказана на новом стенде после полного сброса** — 112031 px
   A/B на pitch 20 с Y=118 (маска: сплошной клин, форма хайтфилда).
2. **Сглаживание v5.2.0 подтверждено на глаз**: усиленный diff показывает
   плавные дуговые ряды вместо пиксельного крапа v5.1.1.
3. **Краска на 400 м почти полностью в тумане** (fog mix ~0.9) — на глаз
   сливается с небом; различима только через усиленный diff. Это корректно
   (Voxy-модель повторяем), но для скриншотов «для людей» краску надо
   смотреть ближе (200-300 м) или с меньшим fog mix.
4. Пыль-стрим живой: точки между кадрами смещаются (верх усиленного diff).
