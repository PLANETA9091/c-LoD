# E2E v5.2.2 — VANTAGE TOUR: покрытие секторов окна с нескольких точек

## Идея

Физика захвата (установлена в v5.2.1): capture-строб видит пыль только на
фоне геометрии (reversed-Z прячет частицы против неба), а клиент с RD8
рендерит ~128 блоков вокруг камеры — ОДИН вантаж закрашивает только свой
диск радиусом ~140 блоков (Y=280, pitch 90: (280-80)*tan(35°) = 140 на
плоскости Y=80). Окно стрима 512x512 (origin = МИНИМАЛЬНЫЙ УГОЛ
(-930,796), окно x[-930,-418] z[796,1308], центр окна (-674,1052)) —
из одной точки покрывается ~20% окна. Все двеллы v5.2.1 стояли на БАШНЕ
в углу окна — красилась только угловая окрестность.

v5.2.2: тур из 10 вантажей — башня (угол) + 4 четверти окна + центр
(волна 1) + южная/восточная кромка (волна 2: F,G,H,I). Каждая нога:
tp (Y=280, pitch 90, spectator) -> двелл 240 с (порциями по 30 с с
`time set 6000` — doDaylightCycle не держится) -> горизонт-кадр ON ->
`posteffect remove Stepan clod:lod_terrain` -> OFF -> re-add -> метрика.

## Метрика

`scripts/bench/paint_diff.py` — персистентный инструмент (раньше считался
inline): пиксель = краска, если любой канал изменился > 15; печатает
секторную карту 8x5 (видно, ГДЕ краска). Замечание: на эталонной паре
v5.2.1 (s70/s71) даёт 15570 px против 17288 старого inline-подсчёта —
порог/семантика чуть отличаются; внутри v5.2.2 метрика сравнивает сама с
собой, числа сессии v5.2.1 несравнимы напрямую.

## ГЛАВНЫЕ НАХОДКИ СЕССИИ

### 1. Тур = ускоритель скана (15x)
Скан полз ~0.5 клетки/с (генерация чанков упирается в CPU — клиент
llvmpipe ест ядро). Каждое tp тура грузит чанки вокруг вантажа на
сервере — кольцевой свип МГНОВЕННО сэмплирует клетки загруженных чанков.
Скан: 35682 (19:16, до тура) -> 54500 (19:58, после волны 1) ->
62591/65536 (95.5%, после волны 2). Вывод: мобильность игрока = скорость
скана; протокол «погонял камеру по диску» должен стать частью каждого
прогона.

### 2. remove/re-add ЧИСТИТ capture-буферы (A/B доказано)
Пост-цепочка при remove освобождает свои таргеты; re-add создаёт их
ЗАНОВО (нулевые) — ping-pong clod_h_*/clod_c_* не переживает тоггл.
A/B: пара ON-кадров «до remove» vs «сразу после re-add» различается на
14981 px (вся картина краски перестраивается). Следствие:
- метрика каждой ноги = декоды ТОЛЬКО ЕЁ двелла (не накопление ног);
- рекорды D/G — собственные 240 с этих ног (на фоне полного скана);
- у РЕАЛЬНОГО игрока (без тогглов) буферы копятся ВСЮ СЕССИЮ — часы;
  рестарты/перелоги — единственный честный сброс;
- протокол стенда: минимизировать remove/re-add, двелл перед ON.

### 3. Тепло чанков клиента
Повторный стеди-кадр на G после перерыва на башне: 9526 px против
рекордных 42372 — клиент выгрузил чанки района G, двелл ушёл на
их рендер. Башня стеди (4 мин непрерывного двелла): 16062 px = уровень
30-минутного двелла v5.2.1 — вокруг башни скан+чанки давно горячие.

### 4. Стабильность
Сервер: 81M+ частиц, 0 failed, шторм-фикс держится, пак НЕ перепушивался
(один пуш при входе; remove/add пост-эффектов пак не трогает). Сессия
клиента 2+ часа без падений.

## Инфраструктурные находки

- **Фоновые процессы в песочнице умирают** при завершении вызова тулза —
  тур запускать ПО ОДНОЙ ноге в переднем плане
  (`run_vantage_tour.sh <leg> 240`), скрипт поддерживает список ног.
- `stream armed: 256x256 cells at (-930,796)` — origin это мин-угол
  окна, НЕ центр; бенч-скрипты исторически называют это "center".

## Модульные изменения

- `src/http.rs` + `src/engine.rs`: /clod-pack.info отдаёт ЖИВЫЕ счётчики
  скана (cells=N/65536 обновляются каждые 100 тиков) — раньше врал
  cells=0 навсегда; sha1/байты пака не трогаются (тест
  set_meta_updates_live_counters_without_touching_pack). 36/36 тестов.
- `scripts/bench/boot_server.sh`: particles_per_tick 1024 -> 2048 —
  лапа 512 -> 256 тиков, вероятность декода бита в минуту x2 (сервер
  проверен на 81M+ спавнов, 0 failed; применится со следующего бута).
- `scripts/bench/paint_diff.py`: новая метрика с секторной картой.
- `scripts/bench/run_vantage_tour.sh`: тур вантажей (ноги tower,A-I,
  настраиваемый dwell, yaw кромок — внутрь окна).
