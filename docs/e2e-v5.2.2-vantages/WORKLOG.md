# E2E v5.2.2 — VANTAGE TOUR: покрытие секторов окна с нескольких точек

## Идея

Физика захвата (установлена в v5.2.1): capture-строб видит пыль только на
фоне геометрии (reversed-Z прячет частицы против неба), а клиент с RD8
рендерит ~128 блоков вокруг камеры — ОДИН вантаж закрашивает только свой
диск радиусом ~140 блоков (Y=280, pitch 90: (280-80)*tan(35°) = 140 на
плоскости Y=80). Окно стрима 512x512 (origin = МИНИМЛЬНЫЙ УГОЛ
(-930,796), окно x[-930,-418] z[796,1308], центр окна (-674,1052)) —
из одной точки покрывается ~20% окна. Все двеллы v5.2.1 стояли на БАШНЕ
в углу окна — красилась только угловая окрестность.

v5.2.2: тур из 6 вантажей — башня (угол) + 4 четверти окна + центр.
Каждая нога: tp (Y=280, pitch 90, spectator) -> двелл 240 с (порциями по
30 с с `time set 6000` — doDaylightCycle не держится) -> горизонт-кадр
ON -> `posteffect remove Stepan clod:lod_terrain` -> OFF -> re-add ->
метрика. Кадры: `shots/`.

## Метрика

`scripts/bench/paint_diff.py` — персистентный инструмент (раньше считался
inline): пиксель = краска, если любой канал изменился > 15; печатает
секторную карту 8x5 (видно, ГДЕ краска). Замечание: на эталонной паре
v5.2.1 (s70/s71) даёт 15570 px против 17288 старого inline-подсчёта —
порог/семантика чуть отличаются; внутри v5.2.2 метрика сравнивает сама с
собой, числа сессии v5.2.1 несравнимы напрямую.

## Что это доказывает

1. **Мульти-вантажный захват живьём**: ноги A-D на 172-460 блоков от
   башни — ВНЕ её радиуса захвата (~140). Их окрестности (11.6-16.2 тыс.
   px краски каждый) декодированы ТОЛЬКО благодаря двеллу на этой ноге.
   До тура эти клетки никогда не каптурились.
2. **Накопление буферов**: рекорд ноги D (28835 px, x2 к любой другой
   ноге) — к четвёртой ноге ping-pong буферы capture накопили сектора
   башни+A+B+C, и марш с вантажа D рисует по ним сплошной горизонт.
3. **Возврат на башню (14331 ≈ 15943 до тура)** — ожидаемо: вид башни
   показывает её окрестность, новые сектора с башни не видны. Краска
   НЕ деградировала — буферы держат накопленное (OFF-паузы и удаление/
   возврат пост-эффекта буферы не чистят).
4. Сервер всю сессию стабилен: 0 failed на 42M+ частиц, шторм-фикс
   держится, пак не перепушивался (один пуш при входе).

## Инфраструктурные находки

- **Фоновые процессы в песочнице умирают** при завершении вызова тулза —
  тур запускать ПО ОДНОЙ ноге в переднем плане
  (`run_vantage_tour.sh <leg> 240`), скрипт поддерживает список ног.
- Скан диска почти встал: 35682/65536 клеток на 19:16, ~0.5 клетки/с —
  генерация чанков упирается в CPU (клиент llvmpipe ест ядро), не в
  лимиты wish-леджера. Гейты GEN не трогали (нет свидетельств, что
  помогло бы).
- `stream armed: 256x256 cells at (-930,796)` — origin это мин-угол
  окна, НЕ центр; бенч-скрипты исторически называют это "center".

## Модульные изменения

- `scripts/bench/boot_server.sh`: particles_per_tick 1024 -> 2048 —
  лапа 512 -> 256 тиков, вероятность декода бита в минуту x2 (сервер
  проверен на 42M+ спавнов, 0 failed; применится со следующего бута).
- `scripts/bench/paint_diff.py`: новая метрика с секторной картой.
- `scripts/bench/run_vantage_tour.sh`: тур вантажей (ноги: tower,A-E,
  настраиваемый dwell).
