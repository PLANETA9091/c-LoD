# Distant Horizons 3.3.4 — пайплайн рождения LOD (разбор исходников)

Источники: `analysis/dh` (тег 3.3.4, GitLab) + `analysis/dh/coreSubProjects` (core-сабмодуль
`6441062`). Пути ниже — от `coreSubProjects/core/src/main/java/com/seibel/distanthorizons/core/`
(`common` — обвязка над MC). Всё ниже — из кода, не из догадок.

## 1. Полные данные: chunk → FullDataSourceV2
`dataObjects/transformers/LodDataBuilder.createFromChunk`:
- Секция = 4×4 чанка (128×128 блоков, SECTION_BLOCK_DETAIL_LEVEL).
- Колонка 1×1 блок сканируется СВЕРХУ ВНИЗ от `max(lightHeightmap, solidHeightmap)`
  (подняться пока не air), раны режутся по смене (biome, blockstate);
  точка = `(id из (biome,state)-мапы, height, bottomY, blockLight, skyLight)`.
  Свет берётся от блока НАД раной (y+1); на верхушке skyLight = 15.
- `forceSingleBlock`: если текущий блок не solid/liquid/opaque (снег-слой, огонь,
  цветы) — следующая точка обязана быть отдельной, чтобы оверлей красил только
  верх колонки.
- Точки кодируются в `FullDataPointUtil` long; слияние одинаковых (id+light)
  подряд — на этапе `RenderDataPointReducingList`/mip-апскейла.

## 2. Render-данные: FullData → RenderDataPoint
`dataObjects/transformers/FullDataToRenderDataTransformer.setRenderColumnView`
(идёт сверху вниз по колонке):
- **Cave culling**: блок не-solid/liquid/полу-прозрачный, skyLight==0, у
  следующей точки тоже skyLight==0, ниже `caveCullingHeight` (default 32 над
  minHeight) → пещера: предыдущая точка продлевается вниз (`setYMin(bottomY)`),
  блок пропускается. Первая/последняя точка колонки не кулятся.
- **Ignored blocks** (`blocksToAvoid`): пропускаются; цвет и свет передаются
  блоку ниже (`tintWithAvoidedBlocks`, по умолчанию true); свет передаётся
  всегда (иначе тёмная сетка на границах LOD).
- **Water under ice**: вода под льдом → лёд.
- **Snow layer 1-3** (и water-surface-replacement): высота точки −1; если слой
  был единственным блоком — красим блок ниже (снег → `snowColor`, иначе
  `waterColor`).
- **Цвет точки** = `levelWrapper.getBlockColor(pos, biome, dataSource, block)`:
  см. §4. Материал = `block.getMaterialId()` (EDhApiBlockMaterial).
- **Вертикальный мердж по цвету**: `color == lastColor && bottomY+height ==
  lastBottom` → предыдущая точка продлевается вниз (две точки в одну). Это
  и есть «слияние» — меш не растёт внутри однотонных колонн.
- Пустая колонка → один `EMPTY_DATA`; void-точка (над бездной) —
  `setVoidAir`: minY=0, alpha=0, material AIR (только для света).

## 3. Квады и коллары: ColumnBox + ColumnRenderBufferBuilder
`dataObjects/render/bufferBuilding/ColumnBox.addBoxQuadsToBuilder`:
- Каждый datapoint колонки = плоско-окрашенный BOX (minX/minY/minZ, ширина
  datapoint'а, высота диапазона).
- **Top-грань** рисуется, если точка выше не начинается ровно на maxY (или она
  прозрачна); **bottom** — если точка ниже не кончается ровно на minY (или
  прозрачна; над бездной нижней грани нет).
- **Боковые грани (коллары)**: для каждого из 4 направлений берётся колонка
  соседа (`ColumnRenderView`), и диапазон [yMin,yMax] текущей точки режется на
  Y-сегменты светом соседа:
  - соседа нет (регион не сгенерирован) → полная стена на всю высоту,
    skyLight = MAX. (На фронтире DH эти стены скрыты туманом: farFogEnd ==
    радиусу данных.)
  - сосед непрозрачен и перекрывает диапазон → сегмент получает
    `SKYLIGHT_COVERED = -1` → **грань не рисуется**.
  - сосед прозрачен → свет берётся у точки НИЖЕ соседа.
  - OVERRDRAW-хак: на границе LOD-регионов (x==0 / z==0 / край) при lit
    соседе грань рисуется даже под перекрытием (дыры при смене детализации).
  - сегменты с skylight >= 0 и высотой > 0 → `addQuadAdj` (стена) со светом
    сегмента.
- **Shade в билд-тайме**: UP 1.0, DOWN 0.5, N/S 0.8, E/W 0.6
  (`ClientLevelWrapper.getShade`, ENABLED-ветка).
- **FADE_TO_DIRT** (`LodQuadBuilder`): нижний ряд вершин стены из травы
  перекрашивается в `getDirtBlockColor()`; GPU интерполирует по пролету стены.
- Полноценный culling данных (`FullDataOcclusionCuller`) выкидывает точки
  колонки, полностью окружённые непрозрачными соседями по 4 сторонам (в
  хайтфилде это «всё, что ниже топа» — у нас не актуально).

## 4. Цвета: ClientBlockStateColorCache (плоские цвета)
На один BlockState один раз:
- **Текстура**: первая непустая грань в порядке UP → unculled → N → E → W → S
  → DOWN; RotatedPillar (брёвна) пропускает UP (кора вместо торца); Slab →
  DOUBLE-вариант; HugeMushroom → default state. Первый quad → его sprite.
- **Средний цвет** (`calculateColorFromTexture`): ПОПИКСЕЛЬНО в ЛИНЕЙНОМ
  пространстве: `r_lin = srgbToLinear(r/255)`, вес = alpha (умножается на
  scale режима); суммы `red += r_lin*a*scale`, `alpha += a*scale`; результат
  `linearToSrgb(sum/alpha)` — обратно через таблицу. Таблицы — стандартный
  sRGB EOTF (таблица ДХ — квантованная версия формулы; байт-разница макс).
  Режимы (EColorMode):
  - `Leaves` (LeavesBlock): пиксели с a==0 пропускаются, остальные a=255.
  - `Flower` (FlowerBlock): пиксели, где `g+25 < b || g+25 < r`, получают вес ×5
    (цветок доминирует над зеленью стебля).
  - `Glass` (имя содержит "glass"): прозрачные пиксели учитываются (сумма 0 —
    no-op).
  - `Chisel`: пиксели не считаются вовсе → цвет (0,255,255,255) = невидимый.
  - Default: a==0 → пропуск.
- Пропавший texture (magenta) → alpha 0 (не рендерится).
- **Ликвиды**: цвет = particle sprite (вода → water_still, первый кадр).
- **Тинт**: если quad тинтованный (`needPostTinting`), цвет = MC color resolver
  (grass/foliage/water для биома в точке) × база: `multiplyARGBwithRGB` =
  целочисленное `(c*t)/255` поканально. Наш `mul_rgb` совпадает.
- Biome tint у DH — живой resolver MC (в т.ч. шум внутри биома); наша статичная
  таблица по биому — согласованное приближение (отличие видно только в
  болотах/саваннах с градиентом).

## 5. ТЕКСТУРНЫЕ LOD (новое в 3.3.x, включено по умолчанию!)
`Config.Client.Advanced.Graphics.Texture`:
- `enableTexturedLods = true` (по умолчанию!), `maxTexturedLodDetailLevel = 2`
  (датапоинты ≤ 4×4 блока получают текстуры; дальние — плоские).
- `BlockTextureRegistry`:
  - На blockstate — «set id» = 6 тайлов (по граням). Нет текстуры грани →
    подстановка UP-тайла (fences/walls/anvils). Все грани плоские → set 0.
  - Тайл 16×16 (спрайт ближайшим сэмплом до 16×16, первый кадр анимации),
    **ratio-кодирование**: `avg` = простое среднее ПО ВИДИМЫМ (a≠0) пикселям
    ПОКАНАЛЬНО (не линейно!); `ratio = round(c/avg * 127.5)`, clamp 255;
    alpha = исходная. Все пиксели == avg → тайл не создаётся (плоский).
    `128 → 1.0`, `255 → 2.0`.
  - Тайл 0 — зарезервированный плоский серый (128,128,128,255).
- **`useBottomTextureForSides`** (`blocksDontUseSideTextureCsv` = grass_block,
  mycelium, nylium, dirt_path, grass + тег grass_blocks/nylium): боковые грани
  текстурируются НИЖНЕЙ текстурой (dirt) — повторяющаяся боковая трава
  выглядит плохо.
- **pickFaceQuad**: при смеси тинтованных и нет (трава+земля на боку) берётся
  НЕтинтованный quad; спрайт копируется «как есть» (тинт остаётся в плоском
  цвете — ratio умножает на него, тинт сохраняется).
- Ликвиды: particle sprite (water_still).
- **Шейдер** (`shaders/terrain/gl/frag.frag`):
  - Плоский цвет идёт из вершины УЖЕ освещённым:
    `vertexColor = lightmap(sky/16, block/16) * shadedColor` (vert.vert).
  - Текстура: `tile = texture(uBlockAtlas, uv)` (с мипами!),
    `clamped = fragColor.rgb * (tile.rgb * 2.0)`,
    `fragColor.rgb = mix(fragColor.rgb, clamped, tile.a)`.
  - UV повторяется на каждый блок грани: `fract(vBlockPos)`; ориентация:
    up `(x,z)`, down `(x,1−z)`, north `(1−x,1−y)`, south `(x,1−y)`,
    west `(z,1−y)`, east `(1−z,1−y)`. У далёких LOD 1 юнит = cell_size блоков →
    горизонтальный повтор = на ячейку; вертикаль всегда по блокам (Y в
    блоковых единицах).
  - **Шум — только на плоских**: `uNoiseEnabled && vTextureTileId == 0u`.
  - Дизеринг/клип (`uDitherDhRendering`) — по конфигу, к геометрии отношения
    не имеет.

## 6. Туман, свет, прочее (проверено в v4.3.0, не менялось)
- Fog: exp-squared, `x = max((d−s)/l,0)*dens`, `1 − range/exp(x²)`,
  farFogStart 0.4, farFogEnd 1.0 × радиус данных, dens 2.5, цвет — мировой
  туман; применяется только к нарисованным LOD-пикселям (`drawnTo` = depth !=
  clear — это НЕ про дыры данных).
- Шум: `applyNoise` — verbatim портирован у нас (steps 4, intensity 0.05,
  dropoff 1024).
- void/несгенерированные данные: стены против отсутствующего соседа РИСУЮТСЯ,
  но сидят на фронтире за туманом. Наше v4.3.0-решение (дыры скана без стен)
  оставлено намеренно: у нас дыры бывают внутри радиуса, где тумана нет;
  отклонение задокументировано в шейдере.

## 7. Что портировано в c-LoD
- `bake_block_colors.py` → точная цветовая математика §4 (линейное усреднение,
  Leaves/Flower/Glass, брёвна→кора, слэбы→DOUBLE, ликвиды→particle).
- `bake_block_textures.py` → ratio-тайлы §5 (16×16, простое видимое среднее,
  useBottomTextureForSides, fallback на UP, дедуп по байтам).
- `atlas.rs`/`jni.rs` → tex_top/tex_side на ячейку (CLODAT03).
- `packgen.rs` + `lod_terrain.json` → текстура тайлов (256 тайлов/ряд) +
  per-cell tile-id текстура.
- `lod_terrain.fsh` → DH UV-повторы, `mix(albedo, albedo*tile*2, tile.a)`,
  шум только на плоских.
- **Avoided blocks (v4.5.0)** → `blocksToIgnore=NON_COLLIDING` +
  `tintWithAvoidedBlocks=true` (дефолты Config.java:895/905, сверено с
  исходником 3.3.4): не-коллизионный/не-ликвид/не-опак блок над поверхностью
  (tall grass, папоротники, цветы, факелы) пропускается, а его цвет +
  материал + тайл ЗАМЕЩАЮТ блок ниже («a red flower will tint the grass
  below it red»); высота остаётся на уровне земли (avoided-блок не даёт
  датапоинта). Над жидким грунтом ветка выключена (seagrass не перекрашивает
  воду — DH держит liquid-ветку). Реализовано в пробе поверхности `jni.rs`
  через `Material#isSolid`/`#isOccluding` (прокси NMS isSolid / opacity 15);
  промах таблицы цветов оставляет цвет грунта — поверхность не сереет.
- **Multi-slice вертикальные данные (v4.9.0)** — полный порт §1/§2/§9.1
  (редьюсер-гэп из §9.1 закрыт):
  - `slices.rs`: 1:1 `RenderDataPointReducingList.reduce(target)` (шаги 0+1
    малый-к-соседу/меньший-сосед/выше при равенстве, 2 стирание между
    равными, 3 форс-мерж дна) + `merge_two_by_two` =
    `FullDataSourceV2.mergeInputTwoByTwoDataColumn` (yTransitions детей,
    голос серединой слайса, air всегда проигрывает, ничья → value0,
    соседние равные сливаются) + таблица MEDIUM из
    `EDhApiVerticalQuality` ({6,6,6,4,4,4,4,4,4,4,1} по detail =
    log2(cell_size)+октава). Последний ран тянется «до дна мира» как
    full-data колонка DH.
  - `jni.rs` скан: колонка проходится ВНИЗ через ChunkSnapshot
    (getChunkAt → getChunkSnapshot → getBlockType), раны режутся по смене
    Material (identity через IsSameObject — Material-enum синглтоны),
    band 0 = примирённая поверхность (снег/вода/avoided как в §2),
    air ран не создаёт (шейдер продлевает верхнюю полосу — эквивалент
    cave-culled обрыва DH), unbaked-материал останавливает проход
    (глубина walk_depth, default 24, конфиг `slice_depth`).
  - `atlas.rs`: SliceCell-таблица (8 raw-ран на ячейку) в CLODAT04-снапшоте
    (блочная компоновка [cells][slices]); `encode_slices` — пирамида
    2×2-голосований + редьюс до MEDIUM[detail] на каждую октаву; стрип
    2n×ΣK·(n>>L), тексель-пары A (RGB цвета + hiY)/B (loY + side-tile id +
    флаги present/liquid/grass), октавы сверх бюджета высоты 8192 падают
    на старый side-pyr путь.
  - `lod_terrain.fsh`: стена банду по hit-Y (`texelFetch`, глубочайшая
    полоса с top ≥ floor(rayY)); FADE_TO_DIRT (грасс-полосы тают в
    getDirtBlockColor() — ColLow — по собственному спану полосы, DH default
    EDhApiGrassSideRendering.FADE_TO_DIRT); side-тайл полосы в текстурном
    пути (useBottomTextureForSides внутри bake).
  - Визуально: стены каньонов = серый камень + dirt-пояса + травяная кромка
    (docs/e2e-2026-10-25-v49-slices/zoom/north_cliff_slices.png против
    north_cliff_v48.png), A/B 4–6.5% кадра — стены, ночь 0.3%.
- **Earth curvature (v4.9.0)** — DH `earthCurveRatio` (Experimental,
  default 0): `uEarthRadius = 6371000/ratio` при |ratio|>1 (иначе выкл),
  в марше каждый ground-тест оценивает вершинный трансформ vert.vert
  `y' = y + (cos(phi)-1)(R+y), phi = d/(R+y)` (два фиксированных шага для
  top-плоскости; xz-сжатие sin(phi)/phi — второй порядок, пропущено);
  конфиг `earth_curve_ratio`, DH-семантика валидации (|r|<50 → ±50).
  Проверено вживую: ratio 5000 (DH max) — земля падает за ванильной зоной
  (docs/e2e-2026-10-25-v49-slices/zoom/curvature_ratio5000_south.png).

## 8. Voxy 0.2.20 A/B — наблюдения по исходникам и живому стенду (v4.5.2)

Voxy (me.cortex.voxy) — второй эталон LOD-рендера, изучен alongside DH:
- **Данные**: Voxy хранит ПОЛНЫЕ воксельные секции (не heightmap как DH!) —
  ingest копирует чанки клиента в lmdb-БД (`.voxy/saves`), каждый join создаёт
  НОВЫЙ world-engine id (seed@hash), старые данные осиротевшие. DH хранит
  производимые heightmap/columns — voxy хранит «сырой мир» и строит пирамиду
  мешей на лету. c-LoD ближе к DH: статичный атлас высот.
- **Рендер**: иерархический HiZ-траверсал на COMPUTE-шейдерах
  (`traversal_dev.comp`, `hiz.comp`) — окклюзионный куллинг от корней пирамиды
  с ридбеком vanilla depth. Требует GLSL 460 (4.6 core): subgroup-опы
  (KHR_shader_subgroup_* — в 450 это расширения, llvmpipe их умеет),
  gl_BaseInstance (ARB_shader_draw_parameters), uint64 за
  ARB_gpu_shader_int64. Патч jar до 450 — в scripts/patch_voxy_gl450.py.
- **Цвет**: voxy ТЕКСТУРНЫЙ (как Voxy-репутация): бейк моделей в атлас
  (SoftwareRasterizer, ModelFactory.MODEL_TEXTURE_SIZE) + освещение/SSAO.
  DH — плоские цвета из среднего. c-LoD = DH-подход (плоские + ratio-тайлы §5).
- **Туман**: post-blit fog (blit_texture_depth_cutout.frag) — линейный рамп
  environmentalStart→End (≈render distance), цвет = environment. При
  FOG_AND_FADE полоса растворяется в небе к краю — у DH exp-squared с farFogStart
  0.4×radius (§6) — поведение близкое, механика другая.
- **Живой стенд**: voxy-клиент на llvmpipe — стек поднят полностью (join,
  мир, ингест ±256 = 75MB БД, полёт, шоты), но LOD-полоса не отрисовывается:
  основной подозреваемый — compute-траверсал/HiZ-ридбек на llvmpipe кульит все
  ноды (geometry строится, не рисуется). Проверка требует F3-энтри voxy
  (не отрисовалось на этом билде) или DEBUG-логов (logconfig 26.3 не подхватил
  logger). Не блокер для c-LoD: A/B против DH (§7) — полный, voxy-суита
  задокументирована в scripts/bench/README.md.

## 9. Верификация по исходникам 3.3.5-dev (GitLab main @ 909282f, core @ c45c13f) — 2026-10-25

Полный повторный проход по свежим исходникам (см. `analysis/dh/src/`) подтвердил §1–§8
и добавил точные константы. Отличий от 3.3.4 в релевантных нам местах НЕТ.

### 9.1 Подтверждено точно (по коду)
- **Шейдинг граней** (`ClientLevelWrapper.getShade`): DOWN 0.5, UP 1.0, N/S 0.8, E/W 0.6 —
  применяется в билдере буфера, в датапоинты НЕ записывается. У нас — SHADE_NS/SHADE_EW +
  down 0.5 в марше. Совпадает.
- **Цвет блока** (`ClientBlockStateColorCache.calculateColorFromTexture`): среднее по ВСЕМ
  пикселям текстуры, alpha-взвешенное, sRGB→linear ДО усреднения, linear→sRGB ПОСЛЕ
  (таблица EOTF: c<=0.04045 ? c/12.92 : ((c+0.055)/1.055)^2.4). Leaves: a==0 пропуск,
  a:=255; Glass: a==0 участвует; Flower: зелёно-доминантные (g+25<b || g+25<r) с весом
  1/5. Тинт биома — по-канальный multiply. bake_block_colors.py совпадает.
- **Ratio-тайлы** (`ClientBlockStateTextureCache.encodeRatio`): `min(round(ch/avg*127.5),255)`
  → 128 = 1.0x, 255 = 2.0x; шейдер: `clamp(fragColor.rgb*(tile.rgb*2.0),0,1)`,
  `mix(albedo, clamped, tile.a)`. Совпадает с нашим lod_terrain.fsh.
- **2×2 LOD-мердж** (`FullDataSourceV2.mergeInputTwoByTwoDataColumn` →
  `determineMostCommonValueInColumnSlice`): все y-границы 4 колонок → слайсы; sample =
  СЕРЕДИНА слайса; победитель = большинство из 4 (air всегда проигрывает, ничья → колонка 0);
  свет = среднее по проголосовавшим ЗА победителя (иначе по всем 4). ВЕРХНЯЯ часть слайса
  [2-й максимум top, 1-й максимум top) голосуется только колонками с max top →
  верх родителя = argmax-height ребёнок (ничья → первый). Наш `pyramid_winners`
  (строгий >, порядок PYR_CHILDREN (0,0),(0,1),(1,0),(1,1)) — точная проекция этого правила
  на heightmap. Совпадает.
- **Окклюзионный куллер** (`FullDataOcclusionCuller`): точка culится, если сверху
  непрозрачно, снизу непрозрачно, все 4 соседа непрозрачны и их top >= top точки;
  culled-точка вливается в точку выше (setBottomY+setHeight). РЕЛЕВАНТНОСТЬ ДЛЯ НАС:
  нулевая — у нас heightmap+марш, скрытая геометрия недостижима для лучей по построению;
  стены рисуются только там, где сосед ниже (эквивалент HAS_* проверки в ColumnBox).
- **Micro-offset**: DH раздвигает вершины квада на ±0.01 блока (uMircoOffset,
  GlDhTerrainShaderProgram) против щелей/z-fighting между LOD-боксами. У нас марш бьёт
  в плоскости точно — эквивалент не нужен (то, что в DH выглядят как щели, у нас
  выглядит как точная граница ячейки).
- **TAA-джиттер** (8 тапов в vert.vert) и **earth curvature** (сферическое сжатие
  `y += (cos(phi)-1)*(R+y)`) — визуальные фичи DH-меша; в posteffect-марше не переносятся,
  осознанно пропущены (кривизна меняет горизонт — при желании добавляется в марш как
  смещение rayY, вне скоупа DH-портации данных).
- **Fog**: farFogStart 0.4, farFogEnd 1.0 (x lodDrawDistance), min 0, max 1,
  EXPONENTIAL_SQUARED, density 2.5, цвет мирового тумана; height-fog и 10 mix-режимов —
  опциональные надстройки, у нас сферический вариант без height-микса (наш горизонт
  уже совпадает с небом по цвету). Совпадает.
- **Вертикальный редьюсер** (`RenderDataPointReducingList`, maxVertSliceCount по
  EDhApiVerticalQuality, MEDIUM = 6,6,6,4… по датапоинтам колонки): экономия числа слайсов
  в МЕШЕ. У нас один cell = один цвет верха + один side-index (mode по боковым слайсам,
  v4.7.1) — та же идея «главное видимое», разница только в том, что DH хранит 6 полос,
  мы одну. Принято как ограничение формата атласа; при переходе на multi-slice атлас —
  правила редьюсера портируются 1:1 (populate → merge step 1 (меньший к равному) →
  step 2 (удаление между равными) → step 3 (форс-мердж дна) → reduceToOne).

### 9.2 Чего в DH НЕТ (фольклор, не портировать)
- Никаких HAS_SOUTH_FACE-флагов в данных (это была правда для старых DH 1.x).
- Никакого per-face AO. Никакого bell/Gaussian-фильтра в LOD-мердже (фильтры только:
  линейное усреднение текстуры и аппаратные мипы атласа тайлов).
- Никакого усреднения ВЫСОТ при мердже — высота родителя = max(valid children),
  «усреднение» появляется только в свете (среднее по проголосовавшим).

### 9.5 Статус после v4.10.0 (2026-10-25)
Закрыты оба оставшихся переносимых гэпа из §9.4:

- **Воздушные раны в стенах → настоящие пещерные проёмы (DH-точные данные).**
  `SliceRun` несёт реальный твёрдый низ рана (`bottom`); скан режет банды
  по воздуху и пишет низы; снапшот CLODAT05; стрип расширен третьим текселом
  C на ряд (ширина 3n: A = RGB+top.hi, B = top.lo+side-tile+flags,
  C = bottom lo/hi). Редьюсер переработан до точного порта
  `RenderDataPointReducingList` ВМЕСТЕ с air-нодами `populate`: между
  несоприкасающимися ранами вставляется невидимый узел; шаг 0+1 сливает
  только same-alpha соседей (быстрый путь SPECIAL_CASES=2 — обратный проход
  без пересортировки, затем общий «от наименьшего с рестартом»); шаг 2
  стирает узел, чьи нижний и верхний соседи равны по альфе ДРУГ ДРУГУ
  (пещерный воздух между солидами заполняется ВЕРХНЕЙ полосой — как у DH);
  шаг 3 прокидывает низший узел вверх сквозь невидимые (lowY сохраняется);
  `copyTo` выпускает только видимые узлы — выживший air = дыра в колонке.
  Заодно найден и исправлен реальный баг v4.9-мерджа: границы накопленного
  датапоинта берутся из СПАНОВ (acc_top/acc_bottom), а не из приватных
  top/bottom победившего дочернего рана — иначе полоса перекрывала соседа
  сверху и переворачивала спаны на следующей октаве. Все-air спан теперь
  ЗАКРЫВАЕТ накопленный датапоинт (он всё равно уходит в выход), а не
  теряет его.
  Рендер: марш спрашивает слайсы входной колонки на каждом граничном
  пересечении — Y в воздушном пазе = грани НЕТ (DH: стена не строится),
  луч летит сквозь уста пещеры (caveDepth); в пещере луч может сесть на
  верхний квад глубокой полосы (пол пещеры — DH рендерит top-квад каждого
  датапоинта); выход выше поверхности соседа сбрасывает caveDepth.
  Осознанное отклонение: свет. DH хранит light-координаты датапоинтов
  (закрытые пещеры ≈ lightmap(0,0), день-независимая тьма); у нас световой
  колонки нет — хит после пройденного паза получает плоскую незажжённую
  замену (albedo × 0.15, стены/пол; промах марша в пещере — тёмная
  константа с обычным туманом по дистанции).
- **Big-atlas стрип-бюджет 8192 → 16384**: продуктовый дефолт
  atlas 4096 / cell 4 (11776 строк) теперь покрывает ВСЕ октавы
  multi-slice стенами; side-pyr остаётся fallback'ом только для конфигов
  за пределами 16384 (например 4096/cell 2 — 22503 строк).

Непортируемые по природе posteffect (без изменений): micro-offset и
TAA-джиттер.

### 9.6 Статус после v4.11.0 (2026-10-26)
Закрыто последнее переносимое отклонение из §9.5 — **световые данные
датапоинтов** (`LodDataBuilder.createFromChunk` 157-260 +
`FullDataSourceV2.mergeInputTwoByTwoDataColumn` 811-943 +
`ColumnBox.makeAdjVerticalQuad` + `terrain/gl/vert.vert` 100-103):

- **Скан**: каждый ран несёт `light = sky<<4|block` — свет блока НАД
  верхом рана (`getBlockSkyLight/getBlockEmittedLight(x, top+1, z)` на
  ChunkSnapshot — 26.3 API держит классические имена); поверхностная полоса
  читает воздух над поверхностью = (0,15) = hardcoded DH-воздух. Бинд
  опциональный: без геттеров полоса 0 → (0xF0), глубже → (0x00)
  (деградация к v4.10-визуалу, не падение).
- **2×2-мердж**: свет усредняется ПО ПРОГОЛОСОВАВШИМ ЗА ПОБЕДИТЕЛЯ
  (`determineAverageValueInColumnSliceWithId` — свет перекрытого блока не
  протекает; целочисленный floor поканально); смена усреднённого света
  ЗАКРЫВАЕТ накопленный датапоинт (DH lines 901-903 — световые переходы
  пещер остаются полосами после мерджа). Редьюсер несёт свет с узлом без
  изменений (выживший хранит своё).
- **Стрип**: байт света в texel C.b (канал был нулевым; ширина 3n не
  изменилась). Формат снапшота CLODAT05 → CLODAT06 (старый .bin = рестарт
  скана).
- **Шейдер**: `slice_band` возвращает свет банды + свет пола гэпа за один
  проход. Стена: sky = свет ВОЗДУШНОГО ГЭПА входной колонки (первая полоса
  ниже хита — «свет берётся у точки ниже соседа»), block = СВОЙ blockLight
  банды (`addQuadAdj`: skyLight соседа + blockLight датапоинта); соседа нет
  → sky MAX (=240 дефолт). Пол пещеры: собственный (sky, block)
  (`addQuadUp`). Освещение — классическая lightmap-кривая x/(4-3x): sky
  умножен на реконструированную дневную яркость (dayF), block несёт
  тёплый тинт (1.0, 0.90, 0.70), пол 0.10 держит незажжённые пещеры
  видимыми (замена плоской albedo×0.15). Незажжённая константа марша
  (hitT<0 в caveDepth) сохранена — у луча за фогом нет ячейки.

Тем самым закрыт весь перечень §9.4/§9.5 переносимых гэпов. Остаются
только непортируемые по природе posteffect: micro-offset (марш точен) и
TAA-джиттер (временной аккумулятор вне скоупа).
